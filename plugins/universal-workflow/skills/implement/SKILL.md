# Implement

1. Read the governing brief, decision notes, and existing materials. If the brief is supplied as a ticket or task reference, retrieve the authoritative item and state its title before starting. Ask for clarification if the reference stays ambiguous or a gap would materially change the outcome. Turn the agreed outcome into observable checks and state any assumptions that affect delivery.
2. Carry out the work in the intended medium and location. Reuse established materials, tools, and conventions. Use a small representative sample or dry run where it can expose a consequential mistake early. For code, use test-driven development at agreed boundaries and the project's established checks.
3. Verify your work against each acceptance criterion in the intended format. Reconcile analysis against source data, inspect a rendered document, walk through an operational plan, or exercise software through its normal entry point, as appropriate. Fix material issues and repeat affected checks.
4. Hand off the governing brief, the actual deliverable or version, checks and results, and any unresolved gaps with their consequences. Follow any review gate specified by the task. Send, publish, deploy, or commit when the task or an applicable workflow calls for it and authorization covers the action.
