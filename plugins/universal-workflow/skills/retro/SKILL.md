# Retro

1. Review the work the user specifies, defaulting to the current session. Compare the intended outcome and acceptance criteria with what happened. Use the available record, including review findings and their resolution, feedback, and the observed outcome. Mark gaps in the record and distinguish observed failures from inferred causes.
2. Trace material wins and friction to a condition the people doing the work can repeat or change. Inspect the existing workflow before proposing a fix. For repeated, objectively detectable errors, prefer improving an existing check or adding one at the point the error first becomes detectable. For judgment calls, improve the brief or review criteria. For time lost finding information, fix the source, access, or its navigation pointer. For costly handoffs, clarify the owner, input, or completion signal. Simplify repeated tool steps or standing instructions when evidence shows they add friction or have no effect.
3. Present the highest-impact improvements first. For each, give the evidence, the smallest change worth trying, and the observable signal that would show it helped. Name a practice worth retaining when the evidence shows it contributed. Use the existing retrospective format or report inline.

Finish with reviewable proposals. Apply changes when the user has also asked you to make them.
